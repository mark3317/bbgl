# Контекст проекта

Работать в корне текущего checkout BBGL. Навыки и рабочие инструкции
переносимы между каталогами и машинами. Подготовка среды и границы
переносимости описаны в [WORKSTATION.md](../../docs/WORKSTATION.md).

Контекст перенесён 13.11.2026 из прежнего дерева; старое дерево сохранено.
Исторические пути ниже описывают происхождение материалов, а не рабочие
каталоги на текущей машине. Контекст, навыки и исследования входят в Git.
`ssh-my-devices` намеренно оставлен вне проекта по указанию пользователя.

## Что изучено

Рабочие правила обоих репозиториев, верхние HANDOFF/ROADMAP/CLAUDE/BACKLOG,
README.ru.md, BUILDING.md, docs/TESTING.md, docs/P2P-HANDOFF.md,
структура исходников, точки запуска, профильные навыки и прежняя память.
Это первичное знакомство с архитектурой и состоянием, а не аудит всего кода.

BBGL — Windows-порт Bloodborne и Python/Qt/QML-лаунчер. BBSC-GL — отдельный
репозиторий, закреплённый подмодулем `mods-src/BBSC`. Основной кооп работает
через локальный Party, LAN/VPN discovery и native UDP. Отдельный VPS/gameserver
для обычного пути не требуется; старые серверные инструкции исторические.

## Практические условия

Путь установки определяется на текущем устройстве. Player 1/2/3 используют
раздельные профили и порты 3658/3659/3660; роли определяются по фактическому
прогону. `П2` означает запуск двух профилей. Фактические install, BB_USER_DIR
и профиль проверять перед будущими операциями.

Инструменты брать из окружения текущей машины. Если Git сообщает о другом
владельце checkout в sandbox, использовать `-c safe.directory` только для
проверенного конкретного репозитория, без глобального wildcard. Тесты Qt
требуют окружения с PySide6; старые venv не копировались из-за абсолютных путей.

После переноса проверены формат навыков, синтаксис скопированных скриптов,
ссылки на рабочие пути и `git diff --check`. Сборка и игровые тесты не выполнялись.
Штатный `quick_validate.py` не запустился из-за отсутствия PyYAML в доступном
Python; обязательные name/description, имена каталогов и границы frontmatter
проверены отдельно. Это не полная YAML-валидация. Копии исследований совпадают
с оригиналами по содержимому.
