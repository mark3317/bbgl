[аудит актуальности](fixes/2026-11-04-full-project-audit.md). Каталог не является списком обязательного запуска.

Unittest-файлы без `unittest.main()` запускать через `python -m unittest discover
-s tests -p ИМЯ_ФАЙЛА.py` (один файл). Для UI использовать
`out/qt-venv/Scripts/python.exe`. Native Python fixtures могут исполняться при
импорте: общий discover недопустим. VPS/Blender/ELF сценарии — только явно выбранные.
Исторические save/profile contracts с explicit skip требуют отдельной миграции.

04.11; не считать весь test_local_party.py зелёным до устранения причины.

## Выбор проверок — 01.11.2026

Выбирать тесты по изменённому поведению и его прямым зависимостям. Полный discover,
все C/C++ harness и игровые прогоны не запускать при каждой доработке/упаковке.
После успешной проверки повторять её только при новых изменениях, сбое или
неразрешённом сомнении. Для правок документации достаточно diff --check.

По разрешению пользователя проверки сейвов и восстановления исключены из
стандартных и обязательных прогонов: post-load recovery, own-world/item recovery,
сохранность сейвов при миграции/обновлении и сравнение хэшей живых сейвов.
Их существующие файлы сохранены для отдельного запроса/расследования регрессии.
В смешанных test-файлах выбирать нужные методы, а не запускать весь файл ради
одной несвязанной проверки. Для изменения самой логики сохранения/восстановления
выполнять непосредственно необходимые проверки; без этого не заявлять её проверенной.
Это правило не отменяет запрет менять реальные сейвы без просьбы пользователя.

- Лаунчер/мастер/маршрутизация: соответствующие test_setup_wizard,
  test_startup_routing, test_launcher_defaults; остальные UI-тесты по затронутому экрану.
- Кнопки/файловые моды: нужные методы test_setup_wizard, test_mods;
  test_file_mods.c только при изменении native файлового слоя.
- Графика/меню/шейдеры/ввод: соответствующие tests/test_*; не собирать все harness.
- Помощник путей/логов: tests/test_coopdev_profile.ps1; реальный collect только
  при изменении сбора логов. Без обязательного чтения/хэширования сейвов.
- Сессии BBSC: test_menu_quit при изменении выхода/его порядка;
  test_hook_resume при изменении trampoline/hooks; test_native_leave_release
  при изменении native leave. test_post_load_recovery не входит в стандартный набор.
- Чаши/follow/matchmaking: test_chalice_scope / test_follow_arrival /
  test_matchmaking_native соответственно. Очереди/scaling — test_pending_work;
  фильтрация диагностик/cache — test_perf_policy. Не запускать их для чистой правки UI.
- Native сеть/диагностика: test_coop_latency_diagnostics и test_p2p_latency_transport
  только при изменении транспорта/его логирования.
- Обычный локальный деплой: BB_FAST_DEPLOY=1, без verify-release и хэшей.
  Релизный пакет: verify-release.py вызывается ОДИН раз внутри package.sh. Не повторять
  вручную после успешной упаковки того же staging. Проверка ZIP нужна при
  изменении упаковки/архивации; smoke собранного лаунчера — при изменении
  заморозки, зависимостей, запуска или жизненного цикла процесса.
- Мод проверять в дереве, которое собирается (для пакета mods-src/BBSC).
  Проверять мод только в подмодуле `mods-src/BBSC`; повторные прогоны без новых изменений не нужны.
  Если отличаются, сначала установить, какая версия действительно входит в пакет.


- Релизное логирование: `python tests/test_release_logging.py` (реальные GPU/DLL sinks,
  фильтрация до форматирования и общий stderr), `test_coop_latency_diagnostics.py`;
  `test_p2p_diagnostic_snapshot.py` проверяет настоящий UDP в обоих режимах.
  BBSC: `tools/test_perf_policy.py` проверяет сохранение функциональных хуков;
  `party/test_logging.py` — отсутствие файлового I/O событий сервиса в релизе.
  Подробности переключателей: [LOGGING.md](LOGGING.md).

- Русская локализация и переносы Qt: `out/qt-venv/Scripts/python.exe tests/test_localization.py`.
  Не требует игры или профилей; геометрия offscreen не заменяет игровой контроль.
  `test_menu_assets.FormatTests` пока имеет отдельный FAIL: устаревшее ожидание ROW_RESTART.

- Перед релизом проверять **английский и русский**: `tools/capture_release_screenshots.py
  --language en --review --output out/l10n/en` и аналогично `--language ru`.
  Запускать через `out/qt-venv/Scripts/python.exe`. Инструмент отрисовывает главный
  экран, все разделы настроек и мастер при обычном/минимальном размере, сохраняет
  снимки и `layout-review.json`. Просмотреть отмеченные тексты и ключевые снимки;
  проверить переносы, варианты списков, кнопки, подстановки и динамические сообщения.
  Дополнить запуском frozen EXE из распакованного итогового ZIP в изолированном
  профиле на обоих языках. CRC сам по себе не доказывает полноту пакета: сверить
  весь список записей и содержимое с проверенным staging, включая Bloodborne.exe,
  run.py, библиотеки Python/DLL и лицензии. Повторять эту проверку после перепаковки.
  Отдельно фиксировать отсутствие визуального контроля добавленного интерфейса
  внутри игры: эти проверки лаунчера не заменяют его.
