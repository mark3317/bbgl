# Работа на другой машине

Контекст разработки хранится в Git этого проекта: AGENTS.md, CLAUDE.md,
`.agents/project-memory/`, `.agents/skills/`, `docs/`, `reports/` и
`research_notes/`. История чатов и старые build/log-каталоги не входят в этот
набор. Для начала работы достаточно прочитать документы, перечисленные в
AGENTS.md; рабочий каталог и имя пользователя могут быть любыми.

## Получение исходников

```sh
git clone --branch develop https://github.com/mark3317/bbgl.git
cd bbgl
git submodule update --init --recursive
```

После clone BBSC находится на закреплённом коммите с detached HEAD — это
обычное состояние подмодуля. Для разработки самого мода проверить его
`origin/develop` и pin родителя. Если они совпадают, переключить BBSC на
`develop` (`git -C mods-src/BBSC switch --track origin/develop` для новой
локальной ветки). Если отличаются, сначала разобраться в разнице, без
автоматического reset или обновления родительского pin.

Проверить status/HEAD обоих репозиториев и `git ls-tree HEAD mods-src/BBSC`.
Обновление родительской ветки и обновление checkout подмодуля — отдельные
действия; локальные изменения сохранять. Для уже существующего checkout
команды clone/init не заменяют проверку его состояния.

## Навыки и доступные инструменты

Локальные навыки лежат в `.agents/skills/` и перечислены в AGENTS.md.
В средах с поддержкой проектных навыков они обнаруживаются автоматически;
в остальных читать соответствующий SKILL.md по ссылке из AGENTS.md.
Три проектных навыка включены целиком с references, метаданными и скриптами.
Других обязательных проектных навыков для локальной разработки нет.

`ssh-my-devices` намеренно не включён и не изменён по указанию пользователя.
Он нужен только при обращении к личным устройствам. Отсутствие этого навыка
не мешает локальному анализу и разработке. Адреса, ключи и доступы на новую
машину отдельно не переносятся; не подбирать их из старой памяти.

Инструменты просмотра других чатов (`list_threads`, `read_thread`,
`wait_threads`) предоставляются средой агента, а не файлами навыка. Перед
общей сборкой соблюдать барьер из bb-coop-build-deploy-logs; если инструменты
недоступны, явно сообщить, что готовность параллельных работ не подтверждена.
Само наличие файлов не доказывает отсутствие других активных доработок.

## Среда сборки

Подготовить Windows x64, Visual Studio C++ Build Tools/Clang, Python и MSYS2
CLANG64 по [BUILDING.md](../BUILDING.md) и
[руководству toolchain](../packaging/windows/README.md).
Зависимости и виртуальные окружения создавать на новой машине, а не
копировать из чужого `out/`. Для UI нужен Python с PySide6. Для штатного
валидатора навыков `quick_validate.py` из skill-creator нужен PyYAML;
общий навык skill-creator относится к среде агента, не к runtime проекта.

MSYS2 может быть установлен в произвольном каталоге. При необходимости
задать `MSYS2_ROOT` реальным путём на текущей машине. Команды `bash` из
навыков выполнять в MSYS2 CLANG64 из корня checkout. Не подменять эту среду
Git Bash и не переносить CMake-кэши, абсолютные пути компилятора или venv.
Полный пакет требует настроенной среды и зависимостей, а не только контекста.

Обычный быстрый деплой и релиз имеют разные проверки. Следовать
[docs/TESTING.md](TESTING.md) и выбранному навыку; перенос документов не
требует сборки игры или полного набора тестов.

## Установка, профили и игра

Путь checkout не задаёт путь игровой установки. Перед деплоем определить
существующую установку на текущем устройстве и каталог для бэкапов.
В примерах operations.md они передаются через `$gameInstall` и `$deployRoot`;
`$repoRoot` и `$skillRoot` вычисляются из текущего checkout.
Проверять значения перед выполнением команд. Если установка ещё не создана,
её подготовка — отдельная операция, а не копирование данных другого ПК.

Профили разрешаются через `%LOCALAPPDATA%` и настройки этой машины.
Фактические BB_USER_DIR, роли и участвовавшие профили определять по текущим
логам/состоянию. `П2` означает два профиля: Player 1 и Player 2.
Игра CUSA03173 1.09, профили, сейвы, аккаунты, SSH-ключи и авторизация GitHub
не поставляются в репозитории. Их отсутствие не мешает работе с кодом,
но ограничивает сборку отдельных ресурсов, публикацию или игровой контроль.

## Исторические материалы

Абсолютные пути и имена прежних устройств в истории HANDOFF, CLAUDE,
fixes и `.agents/project-memory/history-2026-10-29/` сохранены как источники
наблюдений. Они не являются defaults или указаниями изменить текущие профили,
сейвы, сеть либо установку. Приоритет — у актуального AGENTS.md и верхних
разделов HANDOFF/ROADMAP. Открытые игровые сценарии не закрываются переносом.
