## Что реализовано

Протокол состояний описан **до реализации** в
[PROTOCOL.md](../../mods-src/BBSC/experimental/party/PROTOCOL.md).
Общий движок используется независимыми лёгкими клиентами и сетевым компонентом
в существующем процессе `run.py` / `Bloodborne.exe --script`.
Нет запуска прежнего сервера, нового серверного процесса или постоянного сервиса.

Разделены стабильный участник, группа/состав, TCP-соединение, native member ID,
поколение мира и владелец мира. Состав и адреса сохраняются в одноразовом
приглашении. Обнаружение — только unicast; multicast/broadcast не требуется.

Временный координатор меняется с ревизией и не определяет игрового хоста.
Prepare → commit → final с **подтверждением всех участников**, fsync и атомарной
заменой журнала. До final нативное применение колокола и CreateRoom запрещены.
Колокол присоединения остаётся доступным. При разделении сети доступность
принесена в жертву запрету конкурирующих миров. Таймаут не освобождает роль.

Слой совместимости отвечает stock shadNet protobuf и игровым HTTP JSON внутри
клиента: собственная идентичность без внешних аккаунтов, Matching2, комнаты,
актуальные member IDs, callback IDs, signaling endpoints, локальный STUN,
поиск/claim, native kick, сообщения комнаты и relay BBSC. После native kick
роль удерживается до подтверждения ухода гостя. Исчезновение старого сокета
не считается уходом, старые native-запросы после замены соединения отвергаются.

HMAC-SHA256, группа, состав и адрес отправителя проверяются до приёма команды.
Модель доверяет приглашённым участникам; Byzantine-защиты от участника,
знающего общий секрет, нет. Приглашение нельзя публиковать.

Игровые UDP-датаграммы, их границы, виртуальные порты, signaling и содержимое
пакетов Bloodborne сохранены. Собственный TCP-канал используется для управления
и непрозрачных кадров BBSC, с ограниченной очередью, ID/ACK и подавлением
повторной доставки. WorldFlags **не объединяются по типу**: части идут отдельно.
ACK транспортного компонента не означает применение флага игрой; после краша
в окне доставки возможна потеря применения, требующая штатной повторной
синхронизации BBSC. Полная transactional exactly-once семантика игровых эффектов
не заявляется. Чрезмерная очередь/неподтверждённый кадр разрывает локальный
канал, вместо бесконечного воспроизведения устаревших данных.

Роль снимается после явной отмены (Blank/форма звонящего колокола/истечение
собственного поиска) или подтверждённого выхода и полного native drain.
Смерть, загрузка и краткий обрыв не являются таким намерением. Счётчик отмен
защищает новый призыв от позднего отчёта о прежней отмене. Windows mutex и
эксклюзивный bind запрещают одновременные экземпляры одного участника.
Восстановление старого журнала допускает очистку только после свежего отчёта
нового эксклюзивного native-процесса о своём незагружающемся idle-состоянии.
Миграции живого мира нет.

## Проверки без игры

Тесты запускаются **в экспериментальном подмодуле**:

```
python experimental/party/test_processes.py
python experimental/party/test_compat.py
python experimental/party/test_native_gate.py
python experimental/party/test_winhttp_bridge.py
```

- Независимые процессы/профили/порты, согласование только TCP; общая исходная
  копия приглашения — статическая конфигурация, а не файл согласования.
- 1/2/3 участника; одновременные запросы, ровно один победитель; отмена;
  pending admission, повторный вход с новым member incarnation; смена хоста.
- Аварийное завершение участника и координатора после durable prepare;
  восстановление журнала; разделение/восстановление сети; отсутствие выдачи
  роли по локальному таймауту; смена состава; старые решения и поколения.
- Детерминированный seed 731: потери 17%, дублирование 30%, задержка и
  перестановка сообщений. Несколько частей WorldFlags приходят без дублей.
- Реальные loopback shadNet/HTTP/STUN/relay: protobuf/JSON, 64-битные CharaId,
  claim, membership, native kick/error 0xFF000019, сообщения комнаты,
  замена сокета и поздний LeaveRoom от старого соединения.
- 16 кадров WorldFlags через production adapter — совпадают побайтно.
- Неверные HMAC/группа/отправитель и старое поколение отклоняются.
- Реальный Windows trampoline с точными прологами NativeApply/GoodsExecutor:
  отказ до side effect, разрешение после grant; Small Resonant не блокируется.
- Production WinHTTP bridge: grant/deny, native process fence и явная отмена.
- `tools/test_hook_resume.py` и `tools/test_menu_quit.py` — PASS.
- DLL build `exit=0`, четыре прежних предупреждения.
- PyInstaller build `exit=0`; добавлены hidden imports сетевой стандартной
  библиотеки. Замороженный runtime поднимает компонент, получает роль,
  завершает его; команда запуска отдельно проверена без запуска игры.
  Установленный frozen launcher на ноутбуке также прошёл проверку загрузки
  модулей и отдельного профиля, без старта игры.

## Первый пользовательский игровой прогон

1. На обоих устройствах открыть **Play Party.cmd** из указанных установок.
   Выбрать тестового персонажа `testStart`. При необходимости получить блокнот
   и штатные колокола в клинике. Пока никто не звонит, оба остаются в своих мирах.
2. Позвонить в Зовущий колокол почти одновременно. Ожидается один разрешённый
   призыв; второй Зовущий недоступен/не срабатывает без расходования ресурса.
   Записать, кто стал хостом. Затем отменить поиск без гостей и дождаться
   нативного завершения; второй участник должен получить возможность призыва.
3. У второго позвонить в Зовущий, у первого — в Малый Звонкий. Дождаться
   фактического появления обоих персонажей в одном мире, не только signaling.
4. Гостю выйти Пустым выстрелом, дождаться своего мира, войти повторно.
   Хосту завершить сессию Пустым выстрелом; дождаться возвращения гостя и native
   drain. Первый снова становится хостом без перезапуска игр.
5. Одна смерть/загрузка и короткое отключение сети: роль не должна выдаваться
   конкуренту. При неоднозначной связи призыв временно запрещён. Не тестировать
   аварийное завершение на основных установках; лёгкие клиенты уже покрывают его.
6. Завершить игры штатно, сообщить «готово» и наблюдения: кто звонил первым,
   кто был хостом, на каком шаге было расхождение. Игру агент не запускал.

Логи каждого профиля: `party/party-events.jsonl`, `party/party-journal.json`,
`coop/bbsc/logs`, `coop/bbsc/captures`, `user/last_run*.log`.
При сборе **не публиковать** `party/invitation.json` и секретные launch environment.
Сопоставлять group/generation/revision, реальные роли, native события и время
обоих устройств. «Готово» означает запрос сбора этих логов, а не автоматическую
пересборку/новый игровой запуск.

## Границы

Подготовлен LAN-прогон; на ноутбуке при проверке не было активного VPN-адреса.
На ПК есть Radmin `26.148.235.169`, но подменять адрес ноутбука предположением
нельзя. Обнаружение не зависит от broadcast и допускает адреса Tailscale/Radmin
в приглашении. Работоспособность VPN между разными провайдерами **не проверена**.
Собственных ICE/STUN traversal и запасного internet relay нет; достижимость
обеспечивает выбранная VPN. Внешний прямой P2P — отдельный следующий этап.
GNS в нативный канал не добавлялся; сравнение relay не считается оценкой direct P2P.

Все участники сохранённого состава нужны для новых решений. Участник не удаляется
по таймауту. Удаление из состава возможно только единогласно и без мира; добавление
первого этапа — новое приглашение после закрытия прежних игр. Потерянный журнал
нельзя считать обычным восстановлением. При неопределённости роль остаётся занятой.
Общедоступные аккаунты/социальные сервисы и каталог чаш в этот private API не
переносились; вспомогательные онлайн-списки возвращаются пустыми. Первый прогон
проводится в обычной локации. Полное прохождение, чаши, prolonged load и
устойчивость при реальных обрывах пока **не подтверждены в игре**.
