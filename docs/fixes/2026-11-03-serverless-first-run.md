## Подтверждённые дефекты private compatibility

1. `experimental/party/compat.py`, Relay.handle: socket timeout 15 секунд
   применяется к ожиданию следующего кадра даже в здоровом idle. Клиентские mod
   logs показывают цикл «connection lost after 15 s» → reconnect. Сетевой обрыв
   VPN для объяснения не нужен: адаптер сам закрывает loopback connection.
2. NP.handle: timeout 20 секунд на каждом чтении заголовка закрывает здоровый
   idle Matching2. На ноутбуке последний world-list ответ в 06:03:16.022;
   Reader header recv failed в 06:03:36.033, затем 06:03:58.153, 06:04:20.183,
   06:04:42.225, 06:05:04.255, 06:05:26.296. Через примерно две секунды после
   каждого обрыва повторяются login/token/features; контекст/Signaling пересоздаётся.
   Следует отделить deadline неполного кадра/handshake от допустимого idle.
3. Вход через CMD напрямую вызывает run.py, обходя штатный launcher log reader.
   `user/last_run*.log` отсутствует на обоих устройствах. Поэтому основной
   native stdout/exit trace этого запуска не сохранён. Нельзя достраивать
   картину отказа на ПК по одному DLL log.

Эти idle disconnect не меняли владельца мира: поколение осталось 0. Это не
подтверждение инварианта при активной сессии — активной сессии не было.
