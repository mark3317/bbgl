## Подтверждённый блокер входа гостя

`compat.account(who)` создаёт 64-битный NP account ID (в этой группе фактически
52/56 бит). Тот же ID ошибочно используется как UserId игрового HTTP API.
Игра передаёт в summon request 32-битное значение: для ПК1554240143 и для
ноутбука1768214827 — ровно младшие32 бита соответствующих полных ID.

В `http_call(.../request)` адаптер ищет участника сравнением
`account(p) == int(body['TargetUserId'])`. Полный ID не равен усечённому ID,
поэтому существующий знак своего участника отвергается как Unknown claim target.
Оба наблюдаемых призыва прекращаются на этом шаге; cmd102/JoinRoom не появляется.
Это дефект нашего mapping игрового UserId ↔ стабильного участника, а не
доказательство проблемы VPN, signaling или доставки игровых UDP.

Следующее исправление: отделить 64-битный NP account ID от допустимого игровым
API UserId, обеспечить стабильное отображение и проверку уникальности внутри
приглашения. Проверить цепочку login → реальная 32-битная сериализация → sign →
claim → JoinRoom. Прежний fixture передавал Python integer без игрового усечения,
поэтому этот дефект он не покрывал.
