# Разбор изменений и очистка — 04.11.2026

## Область и исходное состояние

Проверены последние коммиты и рабочие изменения BBGL/BBSC, цепочка запуска,
discovery/configuration, упаковка, границы Party/native, изменения admission,
логирования и квестовых guards, актуальные HANDOFF/BACKLOG и тестовые точки входа.
Это целевой разбор текущего кооп-пути, не построчное доказательство корректности
всего renderer/emulator и не игровой прогон.

До фиксации: BBGL HEAD d588b23, gitlink BBSC 5351ecd, фактический HEAD подмодуля
87a1186 плюс большой набор незакоммиченных изменений. По отдельной просьбе
пользователя сохраняется всё состояние проекта: сначала мод, затем родительский
репозиторий с новым pin. Сторонний FSR-подмодуль и __pycache__ исключены.

## Текущая работа

- `launcher/bbport_party.py`: выбор private network, discovery, mesh-проверка,
  согласованная конфигурация группы и имена игроков.
- `run.py` запускает `party/compat.py` внутри собственного процесса. `engine.py`
  согласует состояние группы; loopback NP/HTTP обслуживает native обращения.
  Игровой UDP и согласование Party — разные каналы. Внешний VPS не требуется.
- DLL собирается из `mods-src/BBSC/emulator/mod` и `bloodborne_re.cpp`.
  Native relay/channel/HTTP остаются в сборке и обслуживают совместимость и
  собственные пакеты мода. Их нельзя удалить только из-за серверных названий.
- Последние изменения включают защиту от устаревшей native identity, завершение
  resident summon, последовательный admission, ожидание claim до 16 секунд без
  повторного запроса, выбранные имена, необязательную диагностику, единственного
  владельца last_run.log и личные предпосылки квестовых наград.
- Второй гость/три игрока и выход хоста остаются открытыми. Последний HANDOFF
  отличает новые source-only изменения от ранее установленной сборки.
  Успех fixture не подтверждает исправление в игре; подробные release-логи
  выключены и не позволяют восстановить все причины старых случаев.

## Удалено и сохранено

У `bbport_coop.py` удалены недостижимые поиск релиза BBSC, распаковка/установка
ZIP в старые папки профиля, override/emulator helpers, update_available и их
константы/импорты. Поиск вызовов в launcher/scripts/run/tests/packaging показал,
что рабочий UI использует `download()` как проверку встроенного клиента.
Этот вход, проверка installed и сетевые/сейвовые функции сохранены.

У `packaging/windows/bundle-coop.py` удалены vendor()/extract_vendor(), checksum
старого архива и сетевые импорты: main() уже копирует DLL и семь файлов Party
из подмодуля и не вызывает эти функции. Лицензии сохранены.

Удалён тест удалённого ZIP-extractor и два теста удалённого hosting UI.
Firewall action tests переведены с несуществующих invite/account/server API на
текущий Party launch и явную настройку выбранной подсети. До актуализации они
падали на отсутствующих registration_key/read_invite и старой сигнатуре вызова.

Серверные исходники, исследования, совместимость старых профилей, функции и
тесты сейвов сохранены. Остальные старые тесты `test_coop.py`/profile layout
содержат исторические server API: весь файл не считать актуальным стандартным
набором. Их полная миграция, включая сейвовые сценарии, здесь не выполнялась.

прогон не проводились; реальные сейвы, настройки и файлы игры не менялись.

локальный навык bb-coop-devloop. Навык находится вне Git этого проекта.
