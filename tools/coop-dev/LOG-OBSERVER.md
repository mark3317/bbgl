# Наблюдение за тестовыми профилями 1/2/3

Наблюдатель включён для локальной установки
`D:/Games/Bloodborne/Bloodborne Game Launcher`.
Запускайте существующие `Bloodborne Player 1.cmd`, `2.cmd`, `3.cmd` как обычно.
Общий `scripts/local_party.py` запускает скрытый сборщик; повторный запуск профиля
передаёт заявку уже работающему процессу. Режим `--all` также подключает все профили.
Конфигурация необязательна: без `tools/log-observer.json` в установке автозапуска нет.
При обновлении пакета helper попадёт в scripts; локальная конфигурация не входит
в релиз. `profile-launcher.c` — другой, исторический вход; он здесь не менялся.

Сборщик читает только новые `.log`/`.jsonl` из известных каталогов логов трёх
профилей, `run_*.log`/`last_run*.log` из user_dir и стартовую ошибку local-test.
user_dir определяется по единственному ключу settings и фактическому BB_USER_DIR
из заголовков логов. Сейвы, журнал предметов, игровые ресурсы и прочие payload
не открываются. Токены/пароли с узнаваемыми именами маскируются перед очередью;
произвольные секреты без имени автоматически распознать невозможно.
Старые логи при первом подключении пропускаются. Смена/усечение файла,
незавершённая последняя строка и повтор после сбоя учитываются. Через 30 секунд
после выхода последнего родительского процесса сборщик дочитывает хвост и выходит.

Служебные данные находятся в `out/log-observer` (игнорируются Git):

- `status.json`: состояние сборщика и PID;
- `pending/*.json`: новые фрагменты, ещё не разобранные Codex;
- `done/*.json`: разобранные фрагменты, сохранённые как доказательства;
- `issues.json`: смысловой ключ проблемы → чат и повторные проявления;
- `followups.json`: незавершённые операции для проверки в следующем ходе;
- `cursors.json`: позиции чтения; `requests`: заявки профилей.

Каждую минуту задача Codex **BBGL — разбор логов профилей 1/2/3** возвращается
в чат настройки и выполняет [инструкцию диспетчера](log-observer-dispatch.md).
Пустые циклы не требуют отчёта. Одна причина у нескольких игроков должна
попадать в один чат. Реестр хранится между запусками. Это смысловая группировка
моделью, а не доказанная идентичность причин: первоначальные гипотезы могут
потребовать уточнения. Сами WARN или отсутствие ERROR не доказывают наличие
или отсутствие бага.

Для чатов явно задаётся проект `Bloodborne coop fix`, ID
`b25db2d0-df72-4c85-acba-249ef647359a`, локальный каталог этого репозитория.
Диспетчер использует встроенный create_thread; внешние CLI-сессии не создаются.
В каждом новом чате явно разрешён только разбор: никаких правок файлов,
документации, сборки, установки, запуска игр или изменения сейвов.
Первые причины и выводы — в чате; факт исправления или игрового подтверждения
из этих логов не следует.

**Приложение Codex должно работать для разбора очереди и создания чатов.**
Скрытый сборщик от него не зависит и продолжает сохранять логи до выхода профилей.
После возвращения Codex очередь может обрабатываться с задержкой; за один ход
берётся до восьми пакетов по 64 КиБ. Каталоги done автоматически не удаляются.

Повторная установка (только при закрытых играх/лаунчере):

```powershell
& tools/coop-dev/install-log-observer.ps1
```

Отключить автозапуск (текущий сборщик завершится после выхода профилей):

```powershell
& tools/coop-dev/install-log-observer.ps1 -Disable
```

Периодический разбор отдельно выключается в расписании задач Codex.
Установщик сохраняет резервные копии заменённых скриптов и конфигурации в out.
Он не собирает/не заменяет мод, EXE, настройки или сейвы и не завершает игры.

Проверки: `out/qt-venv/Scripts/python.exe tests/test_log_observer.py`.
Сквозной probe использует искусственные профили в `out/log-observer`, без игры.
В проверочном чате три одинаковых искусственных события сведены в один инцидент;
принадлежность чата проекту проверяется list_threads по projectId и cwd.
